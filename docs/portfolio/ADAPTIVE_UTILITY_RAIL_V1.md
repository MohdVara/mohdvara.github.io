# Adaptive Utility Rail v1

The previous header language disclosure and combined display form hid common preferences. A shared fixed rail now exposes Language, Theme, Text size, Animated scenery and Privacy independently. Navigation retains its existing links and mobile disclosure.

`Experience` mounts one `UtilityRail` outside route Suspense boundaries. This includes localized pages, lazy case studies, Incident Zero/System Defence and the custom 404 shell. The existing 404 renderer/HTTP handling is unchanged by this work.

`UtilityRail` owns disclosure state only. `UtilityPanel` loads on demand; `UtilityPreferences` contains the extracted existing theme, reading-size and analytics controls. The existing scenery control and reading-mode toggle are reused. No dependency, storage key, preference migration, analytics event or consent category was added.

Desktop docking uses `inset-inline-end`, mirrored by the document direction: right for LTR and left for Arabic. A panel opens inward, centered vertically with a viewport-bounded scrolling surface. At widths up to 760px, or heights up to 500px, a named Settings entry expands a horizontal five-control cluster; the panel sits above it. Safe-area insets and footer clearance preserve access at the document end. Controls and panels stay horizontal in vertical CJK reading mode. Desktop reading gutters clear the closed rail at intermediate widths. Native selects provide platform scrolling and keyboard navigation without custom listbox behavior.

Only one nonmodal region opens at a time. Each button announces its name/current effective value and expanded state. The region receives focus without scrolling; Tab remains free to leave. Escape and the close button restore focus to the trigger. Outside pointer, locale/route changes, history and fragment changes dismiss the panel. A successful language selection closes it; a failed locale download keeps the panel, previous selection and error recoverable. Query, fragment, equivalent route and English-original behavior remain in `Experience`. A failed panel-chunk download exposes an explicit reload/retry button.

The rail sits at layer 19, below the header (20) and skip link (100). The mobile navigation closes the rail disclosure and hides its entry while open. Native dialogs, explicit ARIA modals and fullscreen views hide the rail, preserving the active modal's focus handling. No focus trap, backdrop, scroll lock or decorative transition was introduced.

All existing preference services remain authoritative: `theme-preference`/`theme-change`, `text-size-preference`/`text-size-change`, scenery preference/subscription and analytics preference/subscription. Server state is deterministic; effects synchronize saved/effective indicators after hydration. First-time visits now default to Dark at the owner’s request. Valid saved System, Time of day, Light or Dark choices continue to take precedence. Clearing/invalid storage returns to Dark; no-JavaScript CSS also defaults to Dark. System and time-of-day modes remain available. The OS reduced-motion preference takes precedence over enabled scenery. Analytics stays off until explicit valid consent; DNT/GPC suppression is shown separately from stored consent. Opening any panel performs no consent write and never loads PostHog. No analytics implementation was changed.

Seven new source labels have machine translations for every registered target locale, with source hashes and `development-assistant` provenance. Existing translations, disclaimer, script shaping and the English-only PACE-RAG conversation boundary are preserved. No linguistic review approval is claimed. The configured translation-provider command was attempted but credentials/model were unavailable; the development assistant supplied the seven labels instead. Validation retains the repository's 97 editorial warnings, with zero missing/stale entries.

The pre-change entry artifact was 214,099 raw bytes and CSS was 78,909 bytes. Final measurements and initial resource inventory are in `verification/portfolio-adaptive-utility-rail-v1.json`. The unchanged entry ceiling is 215,000 bytes. Deferring detailed panel code is a loading tradeoff, not a claim of faster runtime performance. Case-study, artwork, game and PostHog lazy boundaries remain intact.

Verification uses four SSR-shell tests, existing preference/history/privacy tests, `scripts/utility-rail-qa.mjs`, `scripts/utility-rail-edge-qa.mjs`, `scripts/utility-rail-a11y-qa.mjs`, `scripts/utility-dark-default-qa.mjs` and the updated `scripts/i18n-qa.mjs`. Raw captures/reports live under ignored `output/playwright/utility-*` directories, with unique names for each run. Failed/intermediate runs are retained; only passing final runs count as acceptance evidence. The final unit suite passes 201 tests; the locale suite covers 88 layouts plus 24 final dark-default layouts. Thirty panel accessibility scans pass with zero violations. Dark-first-paint checks block React, emulate a light OS preference and verify all saved theme modes; no-JavaScript Dark and persisted menu overrides also pass. See the verification JSON for exact commands/results and screenshot locations.

Limitations: automated Chrome/axe and scripted keyboard checks do not certify screen-reader behavior. No manual VoiceOver/NVDA, real iOS/Android keyboard, hardware safe-area or physical browser-zoom certification was performed. Small CSS viewports exercise reflow equivalent to reduced available space. Native selects use OS-specific popups. The entry budget has little headroom. No deployment or live Cloudflare verification is claimed.
